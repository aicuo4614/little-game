# 英雄体系大改讨论记录

日期：2026-11-27。本页记录英雄体系和第一关的规则、配表入口与验证范围。

## 已确认

- 用户确认首批四职业为战士、射手、法师、刺客；删除此前方案中的守卫职业，由刺客替换。承伤定位可由战士及具体英雄技能承担，不据此新增独立守卫职业。首批种族和英雄名单见下文。

- 每名英雄一个种族、一个职业，始终拥有普攻，另有三个固定技能。一星解锁技能一，二星增加技能二，三星增加技能三；正式取消原二星技能分支。三个技能允许主动、被动混合，具体组合按英雄设计。
- 盗贼使用不戴帽子的版本。
- 敌我共用单位、属性、职业、技能和 AI 代码，阵营决定友敌关系，不另写敌方专用战斗规则；共用规则不要求双方采用相同阵容与数值配置。
- 所有刺客共有跳后排行为，不占三个英雄技能位置。一星即可拥有，每波最多成功使用一次。
- 跳跃不在开战时立即执行：需要满足检测范围与起跳条件，选择最大跳跃距离内最远敌人，跳至其附近合法落点。具体距离、检测参数待调校。
- 没有合法落点时继续正常行动，不消耗次数，后续重新检测。眩晕、冻结、定身时禁止起跳，解除后再检测。跳跃途中仍可被选中并受伤。
- 用户要求设计 Buff 系统，明确点名 `BattleBuffControl`、`UnitBuffControl`；随后更正第三个为 `UnitStatusControl`，负责单位眩晕、冻结、沉默等状态，状态类型必须定义为枚举。此前 `BattleStatusControl` 名称已被更正，不新增该类。

- 单位属性统一由 `UnitPropertyControl` 管理。首版汇总基础属性、星级成长及 Buff 修正，并按物理防御或魔法抗性结算对应伤害。

- 用户确认主动技能采用类似自走棋的积攒能量释放机制，加入蓝条（法力），不采用此前建议的纯冷却制。用户确认敌我共用普攻命中与受到伤害两种基础回蓝来源，具体回蓝量由实战调校。额外回蓝可由被动或 Buff 提供，属于设计建议。用户确认蓝条满值与所有主动技能的耗蓝均为 100。满蓝时按技能三 → 技能二 → 技能一的优先级选择已解锁且可释放的主动技能。用户确认主动技能可配置独立冷却。高优先级技能处于冷却时，满蓝可按优先级改放其他可用技能。冷却时长由实战调校。用户确认敌我每波均以 0 法力开战，上一波剩余法力不结转。

## 首批阵容和养成（已确认）

- 基础属性由 UnitPropertyControl 统一管理。首批包括最大生命、攻击力、物理防御、魔法抗性、攻击速度、移动速度、普攻射程。物理防御和魔法抗性分别减免对应伤害，成长和减伤公式由实战调校。
- 首批为人类、亡灵两族，共八名英雄。按战士、射手、法师、刺客顺序，人类为骑士、游侠、法师、无帽盗贼，亡灵为骷髅战士、持弩骷髅小兵、骷髅法师、骷髅盗贼。
- 种族羁绊为 2／4 人两档，职业羁绊为 2 人一档。只数上阵的不同英雄，同名重复上阵只计一名，效果作用于对应成员。人类加攻击，亡灵加最大生命，战士加物理防御，射手加攻速，法师加技能伤害，刺客落地后短暂提高伤害。
- 转盘保留职业图案、现有转数和保底，每次中奖从该职业随机获得一名英雄，自动发放。
- 三名同名同星英雄合成高一星英雄，最高三星。保留主英雄站位，升星自动增加对应技能。三星是一局后半段的成长目标，具体产出节奏用完整远征回放调校。
- 敌方职业、星级和站位由关卡配置。前期以一星为主，后期加入二、三星精英。敌我共用战斗规则，首版敌方关卡配置关闭羁绊。

## 第一关测试出怪（已确认）

- 第一关共 10 波。每波由若干小波组成，怪物分批入场。小波按时间间隔触发，每次间隔在配置范围内随机。每个大波开战即出第一小波，后续小波到点即出，允许与前一批同时在场。全部小波出完且场上敌人清空后才过波。
- 怪物分普通、精英、Boss 三类。每逢 5 的倍数为 Boss 波，第一关第 5、10 波各只出一只石甲巨像，两波复用同一 Boss。
- 控制怪物数量和出场节奏。首波安排 2 只普通怪，以能用 1 名英雄应战为调校目标。用户确认首波沿用正常上阵规则，实际人数由招募结果和玩家部署决定。建议将两只普通怪各安排在一小波，用于验证分批刷怪。

## 配表入口

编辑 `Assets/LittleGame/Resources/BattleTables` 下的 UTF-8 CSV，保留列顺序。Unity 导入后退出再进入 Play 即读取新表。战斗、敌情预览、MCP 和纯规则测试读取同一套数据。

| 文件 | 调整内容 |
| --- | --- |
| `stage.csv` | 大波序号、上阵人数上限（0 沿用正常人口）、奖励、敌方羁绊开关 |
| `spawns.csv` | 波次、小波序号、距上批的最小和最大间隔（秒）、怪物 ID、星级、数量、出生路肩方向（lane 0 至 2） |
| `units.csv` | 英雄与怪物共用模型、种族、职业、分类、基础属性、普攻时间轴和技能引用 |
| `skills.csv` | 技能效果、倍率、范围或护盾参数、作用时长、独立冷却与演出引用 |
| `synergies.csv` | 种族或职业、人数档位、属性增益与生效时长 |
| `recruits.csv` | 各职业的随机招募池 |
| `tuning.csv` | 回蓝数值、星级成长倍率、刺客距离及时序、后半程招募权重 |

小波序号从 1 连续递增，第一小波间隔填 0。同一小波的各行共享一组间隔，怪物按各行数量同时入场。随机时间由关卡种子和波次计算，可用 MCP 重开同一局进行复测。第 1 波两小波各出一只普通怪，第 5、10 波各出一只石甲巨像。敌方羁绊在首关全部关闭。

为让三星能在第一关后半段通过正常招募出现，当前配表从第 6 波开始提高已有升星进度的职业与英雄权重。转盘次数、十字中奖、保底和随机发放继续沿用已确认规则。

## Control 首版实现

- `BattleBuffControl` 按阵营和不同英雄身份计算羁绊档位，向匹配成员提供常驻和落地效果。首关通过波次表关闭敌方羁绊。
- `UnitBuffControl` 按来源维护每个单位的效果、刷新和到期，并管理护盾吸收。多层、通用驱散和周期触发仍是后续扩展方向。
- `UnitPropertyControl` 从基础值、星级成长和有效 Buff 计算最终属性。
- `UnitStatusControl` 以枚举保存眩晕、冻结、沉默、定身和减速。多个来源独立到期，移动、普攻、施法和跳跃统一检查状态许可。
- 战斗规则、界面和 MCP 读取共用单位状态。MCP 返回效果来源、结束时间、羁绊档位和法力状态。
