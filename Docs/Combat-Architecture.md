## 目录与依赖

### 2026-11-25 战斗 AI 状态机与移动修正

用户明确要求 AI 使用状态机或行为树。现有自动交战采用 `Domain/BattleAgentBrain.cs` 的确定性有限状态机，不引入行为树运行库。

| 状态 | 进入条件与行为 | 退出条件 |
| --- | --- | --- |
| Idle | 无存活目标，零追击意图 | 获得目标 |
| Pursuing | 目标在站定阈值之外，输出期望速度 | 进入射程内侧、受控、丢失目标或死亡 |
| Engaging | 进入射程内侧后站定，输出攻击许可 | 越过射程外沿、受控、丢失目标或死亡 |
| Controlled | 冻结时零移动/攻击意图 | 控制结束后重新评估 |
| Dead | 死亡后立即归零速度，禁止动作结算 | 波后复活时重置 Idle |

每个固定步依次执行感知/目标选择、状态转移、意图生成、朝向/冷却校验与伤害、统一 ORCA 移动。状态机不依赖 Unity、MCP，也不直接播放动画。当前可攻击目标保持锁定，追击仅在新目标明显更近（0.65m）或旧目标失效时改选；正常集火覆盖可攻击目标选择。

追击进入交战使用内侧阈值（我方射程减0.06m、敌方减0.02m），恢复追击使用实际射程外沿，不扩大我方攻击射程。敌方近战距离至少覆盖双方身体半径和加0.04m，防止重甲单位永远被碰撞阻挡在攻击范围之外。

ORCA 输出保留安全速度，禁止再归一化到最大速度或截断低速；面对不参与调速的站定单位，移动方承担全部避让责任。盾卫追击站位位于身体半径外侧。表现按帧平滑固定20Hz的位置，战斗动画读取规则速度，归队强制走路只在非战斗阶段生效。 走路/待机切换按当前主动作判断，不能因淡出片段仍返回 IsPlaying=true 就跳过切回；受击顿帧单独观测。AI 状态是单波运行态，波后复活或新局重置，不写入长期存档。

验证命令：`dotnet run --project Tools/CombatTests/CombatTests.csproj -- --movement`、`dotnet run --project Tools/CombatTests/CombatTests.csproj -- --movement-report`、`python -X utf8 Tools/Preparation/verify_combat_movement.py`。测试结果不等于手机验证。

## 启动和生命周期

`Combat` 默认场景 → `ClientBootstrap` → 平台服务与 `BattleApplication` → 注册指令路由和视图 → 默认远征直接可操作。新局/重开重建纯状态；帧更新只按固定步长推进战斗。退出 Play 或场景卸载注销 MVC、多余相机与静态引用。玩家与 MCP 同用 `Submit(BattleCommand)`。

快照、事件均由规则层生成；规则修改不直接调用相机、UI 或 MCP。冷却、伤害、胜负与随机必须能在无 Unity 条件下回归。持久化带版本，恢复后校验，写入失败不覆盖旧档。

## 验收

先纯规则回归，再编译与 Play，通过正常 MCP 实际招募、部署、合成、战术、奖励、失败/胜利、重开及状态观察；另走共用 pointer 入口检查取消、拖动和按钮。检查 Console 和真实渲染。Android 设备可用时重新构建安装启动，记录前台进程、画面、触屏与日志；不可用时明确阻塞，不装旧包。


## 2026-11-25 A*战斗导航落地（当前实现，覆盖前述ORCA移动执行部分）

- `ThirdParty/RoyTAStar`：固定MIT核心，独立`LittleGame.RoyTAStar`程序集，保留原许可与SOURCE.json；仅增加查询时动态通行过滤器，不引入WPF或基准工具。
- `Domain/BattleAgentBrain`：选择稳定目标和行为状态，输出交战许可；不再输出实际移动速度。FSM增加Waiting，真正移动/等待由导航执行结果决定，受控与技能占用仍禁止追击。
- `Domain/BattleNavigation`：预订可站且可达的攻击落点，直达优先，否则调用A*；复用0.25m导航图，按本次身体半径检查扫掠通行，安全拉直路线。移动目标明显偏离或路线被占后重新规划，候选落点分批尝试以避免永久卡在最近的一组落点。
- 站定单位不推挤；行进按离目标距离与等待时长排序，后续单位对已执行单位的当步起终位置做相对扫掠校验，防相向互穿。紧密布阵/重叠出生仅允许不加深穿插的离开动作。
- 无路或路线被占即零位移等待，约0.25～0.30逻辑秒后重试；不是每帧左右探测，也不把未完成路径当到达。MCP返回具体阻挡原因、等待时长和路径规划版本。
- `BattleNavigationState`：单波运行态，含路径转角、目标落点、阻挡原因与重试计时；波后/新局重置，不写入长期存档。
- `BattleSession`：统一收集意图，导航执行后写入真实坐标和实际速度，再由表现层读取。边界后的真实位移计算速度，修复被裁剪后仍有虚假速度的缺口。原`BattleRvoAvoidance`已移至`Archive~/NavigationRvo`，当前无双系统并行运行。
- 当前庭院战斗地面没有将装饰物当作碰撞障碍。矩形地形阻挡、U形和窄道在纯规则导航测试中构造，用于验证算法边界，不冒充正常关卡中已有的地形内容。

验证：`dotnet run --project Tools/CombatTests/CombatTests.csproj -- --movement`涵盖FSM、锁定与导航场景；`--movement-report`执行原正常远征规则回归；`python -X utf8 Tools/Preparation/verify_combat_movement.py`执行Unity正常招募、共用输入、完整远征与动作/导航采样。当前验收报告分别位于`Reports/Combat/navigation-domain-tests.json`和`Reports/Combat/astar-navigation-20261125/`，报告存在不等于其状态已通过，必须读取最新结果。手机尚未验证。
